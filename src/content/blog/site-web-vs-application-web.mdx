## La vraie différence en une phrase

**Un site web est consulté. Une application web est utilisée.**

C'est la distinction fondamentale, et elle change tout : le coût, le délai, l'équipe, la maintenance, la stratégie SEO.

### Ce qu'est un site web

Un site web délivre de l'information. L'utilisateur arrive, consomme du contenu, repart. L'interaction se limite à : naviguer entre les pages, scroller, cliquer sur des liens, remplir un formulaire de contact.

**Exemples typiques :**
- Site vitrine d'une entreprise
- Blog éditorial
- Portfolio
- Site institutionnel
- Page de produit (pas de tunnel d'achat)
- Catalogue en ligne (sans panier ni compte utilisateur)

### Ce qu'est une application web

Une application web délivre une fonctionnalité. L'utilisateur s'y connecte, accomplit une tâche, manipule des données qui lui appartiennent.

**Exemples typiques :**
- Outil de gestion de projet (Notion, Trello)
- Plateforme de paiement (Stripe Dashboard)
- Espace client de banque
- Outil de réservation
- Plateforme SaaS B2B
- Réseau social
- E-commerce avec compte utilisateur, panier, suivi de commande

### La zone grise

Beaucoup de produits sont à mi-chemin. Un blog avec un compte utilisateur pour commenter, un site e-commerce avec un panier, un catalogue avec un calculateur de tarif personnalisé.

**Règle pratique :** dès qu'il y a authentification, base de données utilisateur ou logique métier complexe, vous êtes dans le territoire de l'application web. Vous aurez besoin de back-end, de sécurité, de scaling, et donc d'un budget plus conséquent.

## Comparatif détaillé

| Critère | Site web | Application web |
|---|---|---|
| **Objectif** | Informer, présenter, attirer | Permettre une action, gérer des données |
| **Interaction** | Lecture, formulaire de contact | Authentification, manipulation de données |
| **Complexité** | Faible à moyenne | Moyenne à très élevée |
| **Front-end** | Next.js, React, ou WordPress | Next.js, React (avec interactivité poussée) |

| **Budget initial** | 3 000 - 15 000 EUR | 8 000 - 50 000+ EUR |
| **Coûts récurrents** | 50-500 EUR/an | 600-12 000 EUR/an |

## Quand il vous faut un site web

Vous avez besoin d'un site web (et pas d'une application) si :

- Votre objectif est de vous faire connaître ou de générer des leads
- Vos visiteurs ne se "connectent" pas
- Vous n'avez pas de logique métier dans votre offre digitale
- Votre business model n'est pas l'usage d'un outil

**Exemples concrets :**

- Cabinet d'avocats à Lyon → site vitrine
- Restaurant gastronomique → site vitrine + réservation simple par formulaire
- Photographe portfolio → site vitrine
- Cabinet médical avec présentation → site vitrine + lien vers Doctolib pour la prise de rendez-vous
- Marque de cosmétique en lancement → site vitrine + landing page produit

Dans tous ces cas, ajouter une "application" serait sur-ingénierie. Le site fait le job.

## Quand il vous faut une application web

Vous avez besoin d'une application web si :

- Vos utilisateurs accomplissent une tâche récurrente sur votre plateforme
- Vous avez besoin d'authentification (comptes utilisateurs)
- Vous gérez des données personnelles ou métier
- Votre modèle économique repose sur l'usage d'un outil
- Vous facturez par abonnement (SaaS)

**Exemples concrets :**

- Plateforme de coaching avec espace membre privé
- Outil de gestion de planning pour PME
- Marketplace mettant en relation prestataires et clients
- Outil B2B avec intégration API à l'ERP du client
- Réseau social niche
- Plateforme de formation en ligne avec progression utilisateur
- E-commerce avec gestion fine du compte client (suivi, retours, abonnements)

Dans ces cas, un "site web amélioré avec un plugin" est une fausse économie : ça crashera dans les six mois.

## La combinaison gagnante : site marketing + application

Pour la quasi-totalité des SaaS, la stratégie optimale combine les deux :

**Le site marketing** (`votredomaine.com`)
- Présentation du produit
- Pages services et features
- Blog SEO pour attirer du trafic organique
- Tunnel de conversion vers l'inscription
- Stack : Next.js statique, génération à la build

**L'application web** (`app.votredomaine.com`)
- Authentification
- Dashboard utilisateur
- Logique métier
- Paiement
- Stack : Next.js + back-end + base de données

Cette séparation permet d'optimiser chaque partie indépendamment. Le site marketing est ultra-rapide, indexable, focalisé sur la conversion. L'application est ultra-réactive, authentifiée, focalisée sur la productivité.

C'est exactement le modèle utilisé par Notion, Stripe, Linear, Vercel, et la plupart des SaaS modernes.

## Les erreurs classiques

### Erreur 1 : choisir une application web par "fierté"

"Mon concurrent a une plateforme, je dois en avoir une aussi." Pas forcément. Si votre concurrent utilise mal sa plateforme, c'est un boulet pour lui. Construisez ce dont vous avez besoin, pas ce que vous croyez impressionnant.

### Erreur 2 : faire évoluer un site WordPress en application

Ajouter des plugins d'espace membre, de paiement, de réservation à un WordPress crée un patchwork instable. Les plugins se contredisent, la sécurité s'effrite, la performance s'effondre. Au-delà de 3 plugins fonctionnels majeurs, repartez sur une vraie application web.

### Erreur 3 : sous-estimer le coût récurrent d'une application

Une application web coûte 100 à 1 000 EUR par mois minimum en infrastructure (base de données, serveur, monitoring), plus la maintenance évolutive (corrections, ajout de features). Si votre modèle économique ne supporte pas ces 1 200 à 12 000 EUR par an, c'est un signal de revoir le périmètre.

### Erreur 4 : développer une app native quand une PWA suffit

Une application native iOS + Android coûte 30 000 à 100 000 EUR. Une PWA (Progressive Web App) couvre 80 pourcents des besoins pour 8 000 à 25 000 EUR. Pour 90 pourcents des projets B2B, la PWA est le bon choix.

## Comment décider rapidement

Voici les questions à vous poser dans l'ordre.

1. **Mes utilisateurs vont-ils s'authentifier régulièrement ?**
   - Non → site web
   - Oui → application web

2. **Vais-je gérer des données qui appartiennent à l'utilisateur ?**
   - Non → site web suffit
   - Oui → application web

3. **Mon modèle économique repose-t-il sur l'usage d'un outil ?**
   - Non → site web (avec éventuellement une intégration tierce)
   - Oui → application web

4. **Suis-je prêt à investir au moins 8 000 EUR initial + 100 EUR/mois ?**
   - Non → restez sur un site web et utilisez des outils tiers (Calendly, Stripe Checkout, MailerLite)
   - Oui → application web pertinente

Si vous avez répondu "Oui" aux trois premières questions et "Non" à la quatrième, c'est qu'il est trop tôt. Validez votre marché avec un site + outils SaaS tiers avant d'investir dans le développement.
